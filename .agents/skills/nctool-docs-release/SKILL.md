# NCtool 文档与发布准备

先读仓库 [AGENTS.md](../../../AGENTS.md) 与 [文档入口](../../../docs/README.md)。文档事实以源码、组件清单、锁文件及 `.github/workflows/` 为准；用户要文档或发布准备时不扩大成公共 API 或业务代码修改。

## 文档同步

- CLI/WebUI 2.2、核心 2.0 分别描述；旧 Tauri 桌面 GUI 源码已移除，仅保留历史资料。当前指南不沿用旧 CLI、GUI、`nctool.toml` 或内置业务机床/模板承诺。
- 先核对实际参数、动作字段、HTTP 路由、配置路径、保存冲突和历史预检查，再写说明。保持软件验证与任何生产/工艺验收分离。
- 示例优先用 `examples/v2`；在临时 home/workspace 验证采用的命令。默认组合为 `template` + `parameters`，`math` 为唯一可选 feature，需显式编译、启用并在请求 `extensions` 选择。
- 根 README 保留快速开始，详细操作链接到 `docs/`；新增、移动或归档同步导航、Markdown/HTML 及 Issue/PR 模板引用。
- 旧方案放 `docs/archive/legacy/`，阶段审查/验收放 `docs/archive/records/`。原文保留版本、日期、原路径与替代入口；JSON/补丁不重格式化。引用已消失文件时写“历史文件，当前仓库未保留”，不补造链接或证据。
- 状态列当前能力、限制、待验证和证据。路线图仅保留待办，不新增日期承诺；CHANGELOG 以未发布节记录有依据的变化，不推断正式发布日期。
- 第三方库说明用 Context7 查询锁定版本，并核对官方源链接；工具资料不替代本项目源码行为。

## 发布准备

只在任务涉及发布时阅读 [发布说明](../../../docs/RELEASE.md) 和 [贡献指南](../../../docs/CONTRIBUTING.md) 的完整门槛。核对 `v2.*` 标签、CI 前置验证、三平台 target/资产及 SHA-256；现有流程没有 crates.io 上传步骤。

使用 GitHub 工具核对待发布提交的实际 Actions 和资产；PR 触发过滤或分页不完整时只读 `gh` 补证。本地新增检查需明确尚未远端运行。完整门槛含依赖审计，网络失败不标通过；必要的 WebUI 发布冒烟在临时工作区用浏览器工具检查。

用户只要求准备时，输出具体可审阅的版本/说明/验证及剩余项。标签推送、Release 创建、上传、合并和公开评论按当前任务已有授权执行；没有授权就停在完成的准备结果，不从 Skill 推导授权。

## 交付检查

检查相对文件链接与章节锚点、命令和 JSON 示例；归档保持原始字节，现有生成资源与用户修改不被重写。实际日期、平台、源码 SHA 与运行链接随验证记录保存，历史成功不能写成当前已通过。
