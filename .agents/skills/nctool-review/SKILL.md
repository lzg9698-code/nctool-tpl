# NCtool 审查

先读仓库 [AGENTS.md](../../../AGENTS.md)。确认审查范围、基准与提交 SHA；本地未提交内容与远端 PR 分别取证。审查本身不授权修改、提交或发送评论。

## 获取证据

- 本地从 `git status --short`、相关 diff 和调用者入手；不要将用户已有修改全部认作本轮引入。
- PR 使用已安装 GitHub 工具读取 PR diff、检查、Actions 与必要日志。先核对 remote、PR head SHA；分页/空状态不足以证明完整 CI 通过。需要时以只读 `gh` 补充；用户要求处理 PR 时将其附加到当前会话。
- 第三方 API 判断先读锁文件，再用 Context7 解析库 ID 并查对应版本；核对返回的官方链接。不要拿 `main` 的行为直接否定已锁定版本。
- 交互疑点用浏览器工具在隔离 home/workspace 复现，依据实际页面控件操作；对正常、失败及恢复状态取证，不接触用户工作台。

## 沿数据流检查

仅检查改动可能影响的边界；需要详细结构时读 [架构](../../../docs/ARCHITECTURE.md)，协议变动读 [插件协议](../../../docs/PLUGIN_PROTOCOL.md)，HTTP/历史变动读 [系统设计](../../../docs/SYSTEM_DESIGN.md)。

- engine → 资产/SDK/runtime → plugin → CLI composition → WebUI：保持 template-only 可用，领域能力缺失时页面和动作正确退化。
- 表单/JSON → Schema → CLI/HTTP/服务 → 输出：精确 i64、非有限数、对象/null、旧加工标记拒绝与上下文校验在所有相关入口一致，不静默截断或归一化。
- 写入/导入 → 指纹 → 原子提交：陈旧保存拒绝覆盖；失败不损坏资产；引用和快照使用同一版本；混合加工资产包整体拒绝，无部分写入。
- 任务 → 取消/失败 → 导出：失败无部分产物，取消不会挂死外部进程，下一次调用可恢复。
- 历史 → 环境预检查 → 重执行：来源、插件/服务绑定明确；旧记录不伪装环境一致，原记录保持不变。
- WebUI → 草稿 → 刷新/切页 → 输出：恢复、冲突、动作切换与过期导出不交付旧结果。

依赖变更或用户要求安全审计时运行 `python scripts/audit_dependencies.py`，按 [工具指南](../../../docs/CODEX_DEVELOPMENT.md) 解释报告，不自动升级依赖。针对发现运行最小必要复现；完整命令见 [贡献指南](../../../docs/CONTRIBUTING.md)。

## 交付

按影响排序只报告可行动的缺陷：文件/行、具体输入或操作、实际行为、后果与证据。区分已复现、代码可推导与尚待验证，给出适量修复方向。说明已执行检查及覆盖限制；无发现也如实说明剩余风险。若用户只要求审查，完成报告即可；授权修复时继续修复并验证。
