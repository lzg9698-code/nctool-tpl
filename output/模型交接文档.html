三、必须优先处理的问题（P0）

  1. 本地文件读取风险：HTTP 模板详情、inspect、validate、render 当前可复用 CLI 的文件路径解析，可能通过绝对路径、.. 或编码路径读取模板目录外文本。HTTP 必须只接受已注册模板 ID。
  2. 前端未接真实服务：ui/index.html 固定 API.mode = "demo"，使用静态模板、机床和浏览器内渲染器；浏览器结果不保证等于 Core/CLI。
  3. API 契约不一致：后端校验问题使用 warning/message，前端使用 warn/msg；切服务模式后警告统计与文案会失效。
  4. 监听边界：非回环 --host 目前仅告警仍会启动。建议本轮直接拒绝非回环监听，远程访问留待 token/鉴权方案。

四、建议实施顺序

  1. 在 server.rs 建立 HTTP 专用的“仅注册表模板 ID”解析入口，禁止调用 find_template_file 和 CLI 的路径回退；同时校验目录模板符号链接不逃出根目录。
  2. 将 UI host 收紧为 IpAddr/SocketAddr，仅允许回环；先成功绑定，再执行 --open；修复 IPv6 URL 方括号格式。
  3. 用 serde 强类型 DTO 固化请求、响应、生成选项和校验报告；非法字段/类型返回 400，不允许静默回退默认值。
  4. 前端切至 window.location.origin 的同源 server 模式，真实加载模板/机床/详情，并只使用服务端 render 输出。
  5. 补充路由与真实 HTTP 测试：路径攻击、模板列表/详情、validate、render、错误码、413 和输出与 CLI 逐字节一致性。
  6. 修复 Clippy 后运行 fmt、workspace test、Clippy、doc 和 audit；最后同步 PROJECT_STATUS 与 ROADMAP。
