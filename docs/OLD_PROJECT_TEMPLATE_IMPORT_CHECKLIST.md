# 旧项目模板提取与导入清单

把下面整段发给负责操作旧项目和当前项目的 AI，并将 `<旧项目路径>` 替换为实际路径。

---

## 可直接复制给 AI 的任务说明

请从旧项目 `<旧项目路径>` 中盘点并迁移适合当前 NCtool 项目的加工模板，导入到当前项目的 `templates/` 目录。目标是完整、可追溯地移植模板，不要只挑少数示例，也不要凭文件名臆测模板用途。

### 1. 先盘点，再迁移

- 递归检查旧项目内所有可能存放模板的目录和文件，包括 Jinja 模板、NC/G-code 程序片段、主程序/子程序、机床程序，以及被模板引用的 include、宏、变量表和说明文档。
- 同时检查配置文件、脚本和源代码中对模板目录、模板文件、变量名、输出文件名和机床型号的引用，避免漏掉不在 `templates/` 命名目录下的真实模板。
- 先输出一份候选清单：源文件路径、用途、适用工艺/机床、是否可独立使用、依赖文件、迁移建议。标记重复、废弃、空文件、生成产物和无法确认用途的项目；不要静默丢弃。
- 归类时区分可独立渲染的模板与仅供 `include` 的片段。只有确认用途后才决定排除项；排除时记录路径和原因。

### 2. 遵循当前项目的结构

- 模板放在当前项目 `templates/` 下，按工艺分类；机床专用模板放入 `templates/machines/<machine_id>/`。可参考 `templates/README.md` 中已有布局。
- 保留源文件名和可辨认的相对路径；若为符合当前目录约定必须改名或调整路径，记录源路径到目标路径的映射及原因。
- 每个目标模板的清单注册键使用相对 `templates/` 的正斜杠路径，例如 `machines/index_g420/example.j2`。
- 可复用且不完整、只供引用的片段用下划线前缀命名，并在清单中设置 `visible: false`。完整但不希望出现在常规选择列表的模板也可隐藏，但不要把它误标成内部片段。
- 若存在 `include` / `extends` / `import`，检查依赖是否一并迁移；按当前项目要求修正引用为从 `templates/` 根开始的完整路径，并检查依赖闭环。

### 3. 保护加工逻辑和追溯信息

- 逐份保留原始加工指令、参数语义、分支条件、注释、单位、精度、程序号和输出格式。不要自行“优化”工艺、猜测缺失参数、改写坐标或将源项目默认值当成当前模板默认值。
- 不要因为模板能渲染就认定加工正确。旧项目的工艺逻辑和控制器行为需要由熟悉该工艺的人复核。
- 保留版权、作者、来源说明和必要的许可证信息；如源文件包含敏感数据（客户/零件/订单信息、机器凭据或个人信息），先识别并从可迁移内容中移除，记录删改项，不要把敏感信息带入当前项目。
- 迁移不能覆盖当前项目已有文件。发生同名或内容冲突时，保留两侧文件并报告差异及建议目标名，不自行覆盖。

### 4. 适配当前模板运行环境

- 阅读 `docs/TEMPLATE_WRITING_GUIDE.md`，逐项检查旧模板使用的模板语法、过滤器、函数、测试、对象方法和运行时能力是否受当前项目支持。当前项目使用 minijinja；Python Jinja2 等环境中的同名语法不保证兼容。
- 发现不兼容内容时，先做语义等价且可解释的最小改写；无法确认等价时保留原文件内容，将其列为待处理项，不要伪装成已适配。
- 特别核对数学函数的角度/弧度语义、字典访问、字符串/数值转换、缺省值处理、循环与 include 行为，以及旧变量名是否被改动。
- 确认数值输出精度与单位符合源工艺要求；不要为让校验通过而降低精度、删除约束或给尺寸参数增加猜测性的默认值。

### 5. 补充元数据和参数规格

- 更新 `templates/templates.yaml`，为每份可独立使用的模板设置清晰的 `name`、`description`、`category`、`machine`（如适用）、`output_filename`、`output_extension`、`visible` 和 `status`。
- 尚未完成工艺复核的迁移模板使用 `status: unreviewed`；只有完成对应级别的审核后才可提升状态，不得仅因语法检查通过就标记 `verified`。
- 在模板头部补充或整理 `NAME`、`DESCRIPTION`、`PARAMS`，列出实际引用参数的类型、必选性和准确说明；有条件必选参数时，在清单 `params.required_if` 中写明触发条件。
- 检查 `templates/variables.yaml` 是否有适合跨模板复用的变量类型、候选值或派生规则。不要导入源项目针对某个零件/订单/装夹的默认尺寸；不要将只读变量的快照值误当成用户候选值。
- 参数规格必须来自源代码、图纸/工艺资料或明确规则。无法确认的含义、单位、候选范围和条件要标为待确认，不要编造。

### 6. 完成后提供可审查报告

完成文件导入和元数据更新后，给出报告，至少包括：

1. 迁移数量及按工艺/机床分类的统计。
2. 源路径 → 目标路径映射；排除项及理由；冲突项及处理方式。
3. 所有语法/逻辑改写的逐文件说明，以及尚未确认的兼容点。
4. 对每份模板识别到的参数、单位、必选条件、include 依赖和输出扩展名；无法确认之处单列。
5. 文件校验结果：清单键是否都对应文件、include 路径是否存在、模板是否能被当前解析器读取、是否存在未声明变量或未匹配条目。
6. 明确哪些仅完成静态迁移，哪些经过渲染验证，哪些经过工艺人员复核。不要声称做过未实际执行的检查。

### 7. 完成标准

- 候选源模板均有明确结论：已迁移、重复、废弃、非模板、因授权/敏感信息/用途不明而暂缓，并可追溯到具体源路径。
- 迁移文件位于合适目录，依赖完整，引用路径符合当前约定，清单与文件一致。
- 源工艺逻辑未被未经说明地更改，未发生对当前文件的静默覆盖。
- 未审核的加工内容保持 `unreviewed`，报告清楚区分技术兼容性检查与工艺正确性审核。
