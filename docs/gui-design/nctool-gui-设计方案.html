1技术选型与架构决策

1.1 桌面框架对比：Tauri 2 vs Electron vs egui

nctool-tpl 的核心逻辑全部用 Rust 编写，以 nctool-core 纯库形式存在。桌面框架的选择直接决定了 Rust 代码的复用方式和最终包体积。

维度Tauri 2 推荐Electronegui
语言复用Rust 直接引用 nctool-core crate，零 FFI需通过 Node.js 调用 CLI 子进程或 IPC纯 Rust，直接调用
安装包体积~3-8 MB（WebView2 系统内置）~80-150 MB（捆绑 Chromium）~5-15 MB
内存占用~30-60 MB~150-300 MB~20-40 MB
UI 生态完整 Web 前端生态（React/Vue/Svelte）完整 Web 前端生态Rust 即时模式 GUI，生态有限
现有 UI 迁移ui/index.html 可直接迁移，Web 技术栈复用可直接加载现有 HTML需用 Rust 重写全部 UI
Windows 原生体验WebView2（Win10/11 预装）Chromium 内核一致原生绘制，风格自定
学习曲线Rust + Web 前端纯 JS/TSRust + egui API
项目契合度仓库已规划 Tauri 集成，core 纯库设计可用但重UI 复杂度高，egui 不适合表单密集界面
推荐：Tauri 2 — nctool-tpl 的 ARCHITECTURE.md 已明确规划 Tauri GUI 集成，nctool-core 作为纯 Rust 库可被直接引用为 workspace 成员或 Cargo 依赖，无需 FFI 或子进程通信。现有 ui/index.html（138KB 单文件）可平滑迁移为 Tauri 前端。安装包体积控制在 8 MB 以内，适合 CNC 工程师在工业 PC 上快速部署。

1.2 前端框架选择：React vs Vue 3 vs Svelte

维度React 18 推荐Vue 3Svelte 5
生态规模最大，组件库丰富大，中文社区强增长快但总量小
状态管理Zustand/Jotai 轻量Pinia 内置Stores 原生
TypeScript一等公民良好良好
Tauri 模板官方 create-tauri-app 模板官方模板官方模板
现有代码迁移现有 index.html 为原生 JS，React 组件化重构最自然同样可迁移需更多重构

考虑到现有 Web UI 使用原生 JavaScript 构建，React 的组件模型最能匹配从"单文件 HTML"到"组件化桌面应用"的迁移路径，且 @tauri-apps/api 对 React 的集成最成熟。

推荐：React 18 + TypeScript — 理由：① create-tauri-app 官方 React 模板零配置启动；② 工业级表单密集型界面，React Hook + 受控组件模式成熟；③ Zustand 管理全局状态（模板列表、机床配置、当前渲染上下文）轻量且类型安全；④ 现有 index.html 的原生 JS 逻辑可逐组件迁移而非一次性重写。

1.3 与 nctool-core/cli 的集成方案

nctool-tpl 的架构文档要求"所有业务逻辑在 nctool-core 中，CLI 和 Web UI 输出一致"。桌面 GUI 遵循同样的分层原则：

Tauri 的后端（src-tauri/）直接将 nctool-core 作为 Cargo 依赖引入，在 Tauri commands 中调用其公开 API，不需要通过 CLI 子进程或 HTTP 服务器中转。这意味着：

  • 零序列化损耗 — Tauri command 直接调用 Renderer::render()，结果作为 Rust 字符串返回，仅在前端桥接处做一次 JSON 序列化
  • 类型安全 — nctool-core 的 ParamValue、ParamSpec、ValidationIssue 等类型通过 serde 自动序列化为前端 TypeScript 类型
  • 现有 HTTP server 可弃用 — server.rs 的 spec_json 等端点逻辑直接迁移为 Tauri commands，不再需要启动本地 HTTP 服务器
  • 渲染一致性 — 桌面 GUI、CLI、Web UI 三端共享同一套 nctool-core 渲染逻辑，输出字节一致

2界面结构设计

下方为五个核心页面的真实可交互 HTML 视觉原型。点击左侧导航栏切换页面。每个原型用真实 HTML/CSS 渲染，深色工业风格，模拟 Windows 桌面应用窗口。

3.2 关键交互细节

交互场景设计方案
拖拽文件 支持将 .mpf/.spf 文件直接拖到渲染页路径框或模板管理页列表区。Tauri onDrop 事件获取文件路径，自动调用 inspect_template 解析并填充表单。拖拽时路径框高亮蓝色边框 + 虚线动画。
实时预览刷新 变量表单变更 → onChange → 300ms 防抖 → invoke('render_template') → 更新右侧 NC 代码。渲染失败时预览区显示红色错误信息，不中断编辑。预览区右上角显示绿色脉冲点表示「实时更新中」。
错误提示 表单验证错误：输入框红色边框 + 下方红色文字提示。渲染错误：预览区红色区块显示 TplError 变体名和消息。Lint 错误：状态栏红色圆点 + 数字。全部错误均可点击跳转到对应位置。
参数范围提示 ParamSpec 的 min/max/options 字段驱动输入约束。数值超范围时输入框边框变橙，tooltip 显示推荐范围。枚举类型（options）自动渲染为下拉框。
模板搜索 模板管理页顶部搜索框，输入即筛选（按名称、描述、分类匹配），支持模糊匹配。
多窗口对比 Phase 2 功能：可从渲染页「在新窗口打开」创建独立渲染实例，方便对比不同参数的输出结果。

以下 Tauri commands 封装 nctool-core 的公开 API，通过 #[tauri::command] 宏暴露给前端 React 调用。前端使用 invoke('command_name', args) 调用。

4.1 渲染相关 Commands

Rustsrc/commands/render.rs
use nctool_core::renderer::Renderer;
use nctool_core::model::ParamValue;
use serde::{Deserialize, Serialize};

/// 渲染模板，返回 NC 程序文本
/// 对应 CLI: nctool render --template <name> --param k=v ...
/// 前端调用: invoke('render_template', { template, params, line_step, max_line, machine })
#[derive(Serialize)]
pub struct RenderResult {
    pub output: String,           // 渲染后的 NC 程序文本
    pub line_count: u32,       // 生成的代码行数
    pub warnings: Vec<String>,  // 渲染过程中的非致命警告
}

#[tauri::command]
pub async fn render_template(
    template: String,              // 模板名称或文件路径
    params: HashMap<String, ParamValue>,  // 变量参数
    line_step: Option<u32>,      // 行号步长，None 使用默认
    max_line: Option<u32>,      // 最大行号
    machine: Option<String>,    // 机床预设名称
    state: State<AppState>,   // Tauri 管理状态（含 TemplateRegistry）
) -> Result<RenderResult, String> {
    let registry = &state.registry;
    let entry = registry.get(&template)
        .ok_or("模板未找到")?;

    let mut renderer = Renderer::new();
    renderer.set_line_step(line_step.unwrap_or(5));
    renderer.set_max_line(max_line);

    let output = renderer
        .render(entry, &params)
        .map_err(|e| format!("{}", e))?;

    let line_count = output.lines().count() as u32;
    let warnings = renderer.take_warnings();

    Ok(RenderResult { output, line_count, warnings })
}

/// 保存渲染结果到文件
/// 前端调用: invoke('save_nc_file', { content, path })
#[tauri::command]
pub async fn save_nc_file(
    content: String,
    path: String,
) -> Result<(), String> {
    std::fs::write(&path, &content)
        .map_err(|e| format!("保存失败: {}", e))
}

4.2 检查与 Lint Commands

Rustsrc/commands/inspect.rs + lint.rs
use nctool_core::model::ParamSpec;
use nctool_core::validate::{validate_template, ValidationReport};

/// 检查模板，返回变量规格列表
/// 对应 CLI: nctool inspect <template>
/// 前端调用: invoke('inspect_template', { template })
#[derive(Serialize)]
pub struct InspectResult {
    pub template_name: String,
    pub params: Vec<ParamSpec>,        // 参数规格（名称/类型/必填/默认/范围）
    pub categories: Vec<TemplateCategory>, // 分类表
    pub dependencies: Vec<String>,     // include/import 依赖
    pub undeclared: Vec<String>,     // 未声明变量列表
}

#[tauri::command]
pub async fn inspect_template(
    template: String,
    state: State<AppState>,
) -> Result<InspectResult, String> {
    let entry = state.registry.get(&template)
        .ok_or("模板未找到")?;

    let params = entry.params.clone();
    let categories = entry.categories.clone();
    let dependencies = entry.dependencies.clone();
    let undeclared = entry.undeclared.clone();

    Ok(InspectResult {
        template_name: template,
        params, categories, dependencies, undeclared,
    })
}

/// 验证模板语法 + 参数
/// 对应 CLI: nctool validate <template>
/// 前端调用: invoke('validate_template', { template, params })
#[tauri::command]
pub async fn validate_template(
    template: String,
    params: HashMap<String, ParamValue>,
    state: State<AppState>,
) -> Result<ValidationReport, String> {
    let entry = state.registry.get(&template)
        .ok_or("模板未找到")?;
    let report = nctool_core::validate::validate_template(entry, &params);
    Ok(report)
}

/// 静态 Lint 检查（三角函数度制风险等）
/// 对应 CLI: nctool lint <file/template>
/// 前端调用: invoke('lint_template', { template })
#[derive(Serialize)]
pub struct LintResult {
    pub issues: Vec<LintIssue>,
    pub summary: LintSummary,
}

#[derive(Serialize)]
pub struct LintIssue {
    pub level: String,        // "ERROR" | "WARN" | "INFO"
    pub kind: String,         // IssueKind 变体名
    pub message: String,
    pub line: Option<u32>,
    pub param: Option<String>,
    pub snippet: Option<String>,  // 问题行代码片段
}

#[tauri::command]
pub async fn lint_template(
    template: String,
    state: State<AppState>,
) -> Result<LintResult, String> {
    let entry = state.registry.get(&template)
        .ok_or("模板未找到")?;
    let issues = nctool_core::lint::run_lint(entry);
    let summary = summarize(&issues);
    Ok(LintResult { issues, summary })
}

/// 列出所有已注册模板
/// 前端调用: invoke('list_templates')
#[tauri::command]
pub async fn list_templates(
    state: State<AppState>,
) -> Result<Vec<TemplateSummary>, String> {
    let list = state.registry.list()
        .iter()
        .map(|e| TemplateSummary {
            name: e.name.clone(),
            category: e.category.clone(),
            param_count: e.params.len(),
            description: e.description.clone(),
            visible: e.visible,
        })
        .collect();
    Ok(list)
}

/// 添加模板（从文件导入）
/// 前端调用: invoke('add_template', { file_path })
#[tauri::command]
pub async fn add_template(
    file_path: String,
    state: State<AppState<'_>>,
) -> Result<String, String> {
    let source = std::fs::read_to_string(&file_path)
        .map_err(|e| format!("读取失败: {}", e))?;
    let name = state.registry.register_from_source(&source)
        .map_err(|e| format!("注册失败: {}", e))?;
    Ok(name)
}

/// 删除模板
#[tauri::command]
pub async fn remove_template(name: String, state: State<AppState>) -> Result<(), String> {
    state.registry.remove(&name);
    Ok(())
}

    let entry = state.registry.get(&name)
        .ok_or("模板未找到")?;
    Ok(entry.clone())
}
