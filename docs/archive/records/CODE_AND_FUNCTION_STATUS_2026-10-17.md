# 代码精简、代码现状与功能现状报告

日期：2026-10-17。对象：当前 `feat/shared-parameter-inputs` 工作树，HEAD `08ab29620a4fbf390517525e3c488b23c1bd35b1`。

## 1. 总体判断

当前项目已收敛为 **通用 Jinja 文本模板工作台 + 共享参数 + 通用插件运行时 + 可选数学扩展**。内置 NC、机床、加工参数、工序、同步粗车、越程槽和轨迹能力已从活动源码、装配、前端和示例中移除。

精简有三个层次：删除加工领域实现；删除未接入生产入口的第二套工作台；移除无消费者分支和依赖、把重资源改为按需加载。通用能力仍然保留任务、历史、冻结输入、精确数值、Schema、指纹冲突、原子写入与插件进程恢复，因此项目并非只有模板编辑和字符串替换。

**当前最需要继续处理的是活动 App 的复杂度、首次使用引导、历史规模管理、状态文档同步和最终发行验证。** 不建议为了继续压缩代码而削弱参数来源、快照、冲突或兼容拒绝边界。

这份报告是现状盘点，不是全面缺陷审查，也不是发行签收。此次未修改业务源码、未提交、推送或发布。

## 5. 旧数据的兼容现状

“保留数据”与“继续运行旧加工功能”是不同的产品边界：

- 用户模板、参数、历史和浏览器草稿不因移除而删除。
- 带 `metadata.nc`（包括 null）或退役加工动作的模板拒绝执行；实际加载的冻结来源也不能降级为普通渲染。
- 旧加工历史可查看、比较、导出原成功产物，不能重跑或恢复成可执行文档。
- 含退役加工集合的混合资产包整体拒绝。
- 退役插件 ID 和动作/服务命名空间拒绝被同名外部插件接管。
- 旧 `nc` profile 拒绝直接启动；配置迁移先只读检查，再以显式指纹确认、备份和原子写入完成，启动不自动改写配置。
- 较老模板快照缺少来源 metadata 时，执行依赖可能返回兼容错误，而不是猜测安全性。

因此，当前源码中残留的 `nc` 字符串不能直接视为未清理功能；其中一部分是必要的拒绝、迁移和历史保护逻辑。
