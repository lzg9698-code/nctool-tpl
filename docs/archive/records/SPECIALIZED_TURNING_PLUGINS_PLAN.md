# 同步粗车与越程槽专用插件方案

日期：2026-10-08。状态：已实施第一版专用插件与受约束轨迹预设，详见`docs/SPECIALIZED_TURNING_PLUGINS.md`（历史文件，当前仓库未保留，原字节见恢复包）及[实际验证记录](SPECIALIZED_TURNING_2026-10-08.md)。下文保留规划时的现状和目标，不能用作完成清单。任意图形节点编辑、旧自由模板程序解析预览尚未提供；专用页面使用同源计划的名义坐标示意。保留已有未提交改动，V3 源项目只读。

## 1. 目标与现状

将同步粗车和越程槽分别做成可独立启停的内置 NC 插件，迁移 V3 的业务输入方式、联动、辅助计算、批量生成和预览。前端使用 React 专用页面，计算、校验和编号推进由 Rust 后端完成；CLI、HTTP、WebUI、组合任务共用这些后端能力。

当前 `plugins/nc/src/operation.rs` 已有 `sync.left`、`sync.right` 和 `groove` 的单条生成计算，但页面主要使用通用 Schema 表单。V3 的多行业务表格、左右分区、ap2 批量推荐、标准选择联动和 2D 预览尚未形成完整专用工作流。当前 Rust 也没有 `recommend_sync_parameters` / `batch_recommend_sync_parameters` 的对应推荐功能。

源码核对范围：

| 功能 | V3 来源 | 当前落点 |
| --- | --- | --- |
| 同步粗车页面与推荐调用 | `ui/sync_turning_frame.py`、`ui/widgets.py: StepTable` | 通用模板表单 / NC 生成页 |
| 刀次、实际起点、双通道、同步推进、ap2 推荐 | `core/sync_turning.py` | `plugins/nc/src/operation.rs: sync`，推荐待补 |
| 越程槽页面与 ES/FS 行控件 | `ui/undercut_frame.py`、`ui/widgets.py: UndercutRow` | 通用 Schema 表单 |
| 标准、几何和批量生成 | `core/undercut_logic.py` | `operation.rs: groove`、`operation_standards.json` |
| 2D 预览 | `core/gcode_parser.py`、`ui/toolpath_canvas.py` | 本次迁移范围 |
| 会话配置 | `configs/turning_config.json`、`configs/undercut_config.json` | 仅作为显式会话导入来源，不变成共享默认 |

## 2. 两个业务插件

| 插件 | 后端目录 / 页面 | 职责 |
| --- | --- | --- |
| `sync-turning` 同步粗车 | `plugins/sync-turning/`、`ui/src/plugins/SyncTurningView.tsx` | 左右台阶表、ap2 推荐、批量刀次与同步号计算、双通道输出、计算诊断 |
| `undercut` 越程槽 | `plugins/undercut/`、`ui/src/plugins/UndercutView.tsx` | ES/FS 标准查询、条件输入、左右多槽批量计算、几何预览及输出 |

它们是 Rust 内置插件配合已注册 WebUI 视图，不恢复旧 Tk/Tauri 程序，也不执行第三方前端脚本。通过 composition root 装配进 `nc-bundle` / NC profile；默认 template 组合不增加 NC 依赖。

每个插件拥有自己的原始输入 Schema、校验、计算、业务会话和版本化服务。共享参数定义、刀具/材料/加工预置、模板存储、机床及后处理继续复用现有底座。无需复制第二套参数管理或模板引擎。

## 3. 同步粗车页面

### 布局与输入

顶部放同步进给、机床选择、会话加载/保存。正文沿用 V3 的空间关系：左侧输入，右侧程序；上半区右侧粗车，下半区左侧粗车。

每侧包含：

- 同步起始号、固定 ap1、ap2 最小/最大值、计算 ap2 按钮。
- 可增删、复制和调整顺序的台阶表：序号、起始直径 X、起始位置 Z、结束直径 X、结束位置 Z、ap2、只读实际刀次。
- 推荐结果区：推荐 ap2、采用状态、无解原因、实际起始直径；左侧还显示修正后的起始 Z。
- 对应的 CH1 / CH2 两个输出区，以及代码/2D 切换、诊断、复制、独立 SPF 导出。

宽屏保留四个通道预览的对照关系；窄屏切换左右侧和通道标签，输入与结果允许独立滚动。表头固定，输入框保留足够宽度，不能靠压缩表格维持四块同时显示。

V3 把名为 `ap_1` 的表格格子作为“刀数”显示，生成时又以侧别固定 ap1 覆盖它。新模型拆成固定 ap1、行 ap2、只读 cut_count，刀次不再作为原始输入，也不混用字段。ap1/ap2 按原算法的 X 直径减量含义标注，不能误标成半径切深。进给模式应取模板/机床声明并展示，缺失时要求明确配置。

### 推荐与生成

迁移原推荐搜索：N 从 1 到 4999，按直径差/N 求平均减量，再计算 ap2；范围比较保留 1e-9 容差。推荐与生成是两个明确动作：推荐不生成程序，采用推荐只更新本次行值。

同时记录推荐原值、V3 的两位显示值及实际采用值。生成以用户看到的采用值重算刀次和起点，不把隐藏的高精度值偷偷用于 NC 输出。若两位量化后越界、得到不允许的零 ap2，或者推荐刀次与实际刀次发生变化，必须显示诊断，不把候选标成已验证可生成。对原 V3 行为的这些差异单独记录。

保留现有生成算法：刀次近整数判定 1e-8、最多 10000 刀、实际起始直径反推、左侧 25° 起点修正、同步编号推进及无需切削分支。每侧批次按行顺序生成，下一行使用上一行的同步结束号，前端不得自行推进。

提供“生成右侧”“生成左侧”“生成全部”。单侧任务失败不交付该侧任何通道；全部任务失败不交付任何侧别或通道。已有结果只可作为明确标注的历史查看，不能冒充本次成功结果。

## 4. 越程槽页面

顶部放毛坯直径、安全距离、机床和会话操作。正文同样采用右侧槽输入/输出在上、左侧槽输入/输出在下的布局。

每侧为多行槽表：序号、ES/FS、标准、D1、Z，以及 ES 专用的 D2、C、角度。保留增删行，并增加复制、顺序调整和行内错误定位。

- 标准从后端返回，按 ES/FS 筛选，显示名称和关键尺寸；不要求手填 `std_key`。
- ES/FS 切换即时更新可用标准和字段。FS 不提交 D2/C/角度；切回 ES 可恢复该行 ES 草稿，保留值不表示它仍被用于 FS 计算。
- 切换类型不自动替用户选定新标准，提供明确选择；标准来源和版本随本次计算冻结。
- 旁边显示标准截面示意、关键尺寸和计算结果：安全起点、切割/补偿坐标、角度、圆角与左右变换。
- 右侧输出按业务侧别预览程序和 2D 路径，可分别生成、复制和导出。

原始行使用统一的 `d1/z/d2/c/angle` 模型；插件在后端映射成相应 ES/FS 上下文。用户无需填写 `ES_Z`、`D1_CUT`、`ANG_1` 等派生字段，也不会同时看到两套不相关的 ES/FS 输入。

纯空行是草稿，不参与生成；部分填写行必须补全并通过校验。至少有一条有效槽；任一参与行失败均拒绝整个所选批次，诊断带侧别、稳定行 ID、当前行号和字段路径。

## 5. 轨迹预设与可调整路径

两个插件从第一版就把轨迹预设作为独立业务资产。加工预置决定转速、进给等加工推荐；轨迹预设决定进刀、切削、退刀、同步与收尾方式，两者分开选择和记录。不能把路径永久写死在插件或模板中，再依靠修改 Jinja 文本调整。

### 计算、路径与程序的分工

统一流程扩展为：

```text
原始输入 + 加工选择 + 轨迹预设及本次调整
    → 几何/刀次计算 → 有类型的轨迹计划 → 路径校验
    → 程序渲染与后处理 → 完整产物
                         ↘ 同一轨迹计划生成 2D 预览
```

几何计算负责标准尺寸、左右变换、实际起点和可用几何锚点；轨迹策略负责将这些锚点编排成运动、补偿和同步步骤；模板负责机床方言、头尾和程序格式。轨迹计划包含侧别、物理通道、阶段、运动类型、坐标模式、进给模式、补偿状态及同步事件，并通过版本化 JSON 契约传递，模型留在 NC 层，不进入通用参数库或根引擎。

V3 的路径逻辑同时存在于 Python 计算与模板中，迁移要逐项归属。尤其左侧同步粗车的 25° 同时影响实际起始 Z 和进刀关系；未来调整该角度必须由同一策略参数驱动几何和路径，不能只改模板 ANG。越程槽的标准圆角、深度和几何关系仍由标准决定，轨迹调整不能绕过或覆盖标准；修改标准几何需要明确的自定义标准或新计算策略。

### 可调整范围与约束

| 插件 | 轨迹预设的可调整内容 | 必须保持的关系 |
| --- | --- | --- |
| 同步粗车 | 进刀/退刀余量、允许的接近顺序、各阶段进给、退刀方式、收尾位置；耦合角度作为策略参数扩展 | 两通道成对计划、共同同步事件、刀次和起点一致、左右侧能力匹配 |
| 越程槽 | 接近与退出距离、进退刀步骤、阶段进给、允许的补偿进入/退出方式 | ES/FS 标准几何、左右映射、补偿状态闭合及机床支持 |

首版只开放已实现并通过校验的参数和阶段选项。新增切削拓扑、不同刀次算法或新的同步策略属于插件策略扩展，需要对应实现和算法版本，不能用任意文本片段替代。后续可增加受约束的阶段编辑器；不开放 Python、eval、任意脚本或无限制 G-code 拼接。

同步预设管理完整的 CH1/CH2 配对轨迹。同步点先用符号事件表示，再由批次调度器统一分配实际编号；禁止独立修改某通道 WAITM、删除单边同步点或人工指定派生编号。左右业务侧各选适用预设；同侧两通道不能各自选择不相关预设。

路径校验至少检查数值、引用锚点、允许的阶段顺序、坐标/进给模式切换、刀补进入和退出、同步事件配对及机床方言支持。可检查的几何边界由策略明确声明；这些检查不等于机床碰撞仿真或工艺审核。

### 资产与交互

轨迹预设包含稳定 ID、格式版本、修订/指纹、所属插件、策略 ID/版本、适用侧别及 ES/FS 类型、机床能力要求、参数 Schema/单位、阶段选项、来源和说明。两个插件拥有各自的预设目录与校验器，共享资产写入机制；不能把轨迹当成共享参数默认值。

内置“V3 兼容轨迹”保留原行为和输出对照基线。页面提供“轨迹预设”区域：选择、复制新建、调整参数、恢复预设值、查看路径及程序差异、应用本次调整、保存为新预设。内置基线通过复制产生可编辑版本。临时调整只影响本次会话，生成不自动保存预设或修改默认选择。

每侧默认使用一个预设，第一版批次中所有行继承该侧预设；预留逐行显式覆盖的请求结构和来源记录。逐行覆盖仍须通过同侧调度器检查，不能破坏同步编号连续性。调整后先更新诊断与预览，原结果立即失效；不能因预览成功自动把调整标记为已确认。

预设编辑使用 JsonStore/WriteKernel、基线指纹、原子写入和独立草稿，支持导入/导出。保存冲突保留草稿；预设选择、本次覆盖和确认状态进入任务依赖。修改模板中承载路径的逻辑也属于轨迹变化，不能绕过失效检查。

### 模板兼容与实施边界

迁移模板逐步改为消费轨迹计划，先以 V3 兼容策略验证最终程序完全对照，再开放调整。路径预览从生成程序使用的同一计划派生，避免维护两套运动公式。机床方言无法可靠表示的路径拒绝生成。

用户模板需声明是否支持轨迹计划及其版本。旧的自由编排模板保留兼容入口，但不宣称支持轨迹编辑或预览与程序一致；专用页明确显示能力限制，不能静默忽略所选预设。自由模板解析出的预览继续标记为有限示意。

第一阶段交付预设资产、V3 兼容策略、轨迹计划、参数调整、预览及快照闭环。图形拖动节点、任意插入运动和完整自定义轨迹编辑留在后续阶段，沿用本次契约扩展。

## 6. 计算与服务边界

不能简单让 `nc.generate.managed` 调用专用插件，而专用插件又调用同一个受管生成服务。目前运行时按插件声明检查依赖并拒绝循环，没有可直接套用的可选依赖字段。

实施前先把共享 NC 能力与受管业务分派拆开，形成单向依赖：

```text
通用模板 / 参数底座
        ↓
共享 NC 资产解析、冻结会话、上下文校验、渲染与后处理
        ↓
sync-turning / undercut：业务 Schema、推荐、计算、批量生成
        ↓
受管兼容分派：原 nc.operation.prepare / nc.generate.managed
        ↓
多工序组合
```

两个业务插件调用下层冻结和渲染能力，不反向调用上层受管分派。专用生成与兼容分派使用同一套业务计算实现，派生字段在专用/受管 API 中均由后端计算，禁止注入伪造值。

业务服务建议如下，均为新服务名的 v1：

| 服务 | 内容 |
| --- | --- |
| `sync-turning.describe` | 原始 Schema、字段说明、单位、模板绑定、轨迹能力、支持的输出 |
| `sync-turning.recommend` | 单侧/多行 ap2 推荐，逐行结果和采用诊断 |
| `sync-turning.prepare` | 原始台阶输入及轨迹选择 → 双通道上下文、刀次、起点、同步游标、轨迹/输出计划及诊断 |
| `sync-turning.generate` | 单侧或全部批量生成、冻结快照、完整产物 |
| `undercut.describe` / `undercut.standards` | 原始条件 Schema、标准目录及尺寸、轨迹能力 |
| `undercut.prepare` | 原始槽表及轨迹选择 → 校验、几何上下文、轨迹计划和预览数据 |
| `undercut.generate` | 所选侧别批量生成、冻结快照、完整产物 |
| `<plugin>.trajectory.list/get/save` | 插件轨迹预设查询、读取和带基线指纹的保存；由插件校验适用性和策略版本 |

describe、推荐/prepare 与 generate 返回自己的输入/资源指纹。前端只编辑、选择和展示；计算结果不能跨不同指纹复用，过期预览不能被当成可生成证明。

兼容层保留现有 `sync.left`、`sync.right`、`groove` 操作 ID、稳定模板 ID、旧请求结构和算法版本语义。composition root 根据启用插件构造服务路由与依赖声明；未启用某插件时，对应业务入口和路由不可用，但其他已启用业务仍能启动。不能因关闭一个业务插件强制破坏所有 NC 功能，也不能静默退回旧通用表单。

引擎、通用 SDK/runtime/assets 和参数底座不加入车削模型；工序插件仍以版本化 JSON 服务消费 NC 能力。共享渲染服务保留 Schema/specs、类型、非有限数、精确整数、单位、机床上限及取消检查。

## 7. 模板入口、资产与组合

导航直接提供“同步粗车”“越程槽”。普通使用者从专用页面操作；模板编写仍留在模板工作台。

三份现有迁移模板可增加通用执行视图提示，由能力注册表把“使用模板”转到相应专用页面。已有单条上下文可显式转换为该页面的一行输入，不混入派生上下文。插件不可用时说明所缺能力，不普通渲染后再报中间变量缺失。

专用页提供模板绑定与配套资产状态。缺少必要模板/标准时，在页内预检查并显式初始化配套资产；保留同名冲突和基线指纹，不能启动时静默覆盖用户模板，也不能让用户自行寻找三个模板才能发现功能。模板仍可更换为兼容业务契约的用户版本。

每个插件有独立业务会话集合，保存全局输入、侧别参数、多行原始值、明确选择、轨迹预设引用、本次覆盖及确认状态、模板绑定和格式版本，复用 JsonStore/WriteKernel。浏览器草稿按工作区、插件、侧别隔离，保留空值、未完成数值和非法 JSON 原文；刷新不丢失，保存冲突保留草稿。共享定义/default、会话、草稿和运行结果分别管理。

V3 turning/undercut 配置可显式导入为业务会话，提供字段转换与缺失项报告。源尺寸和临时加工记录不成为共享默认，旧程序文本不导入为当前生成结果。

“加入组合”输出可执行工序定义和明确的侧别/通道标识；组合任务从这些原始输入重新生成，或者使用明确冻结快照，两者互斥。主程序绑定本次生成片段，不写入变量库历史程序默认。所有工序、文件共享冻结资源，任一步失败不交付部分结果。

## 8. 预览、失效与历史

迁移 V3 的代码与 2D 切换、缩放/适应范围、复制和生成时间展示。2D 作为完整交互范围中的验收项。

V3 的 G-code 解析器对 ANG/RND 等只作有限示意，并不是完整机床模拟。支持轨迹计划的模板使用同一计划生成代码和预览；旧自由模板由后端解析提供路径点和能力标记，前端只负责 Canvas/SVG 绘制。业务几何示意、计划路径和程序解析示意分别标注，未解析的指令显示提示，不能称作刀补、圆弧或碰撞仿真。

任意行值、侧别公共值、标准、推荐采用状态、轨迹预设/覆盖/确认状态、策略版本、模板、机床变化都更新指纹。全局值使双方结果失效，单侧输入只使本侧结果失效；全部生成结果依赖双方。复制、导出、加入组合必须检查当前结果有效性，历史查看保留。

后台任务支持取消；用户编辑后晚到的结果不得覆盖新输入。每次成功记录原始业务输入、已采用推荐、标准/模板/机床快照、轨迹预设完整内容与覆盖/确认状态、算法和策略版本、计算结果、轨迹/通道计划和实际服务绑定。历史重执行使用原快照并核对环境，不改写旧记录；原策略版本不可执行时明确拒绝，不能替换为新策略继续生成。

## 9. 实施与验收

1. 冻结源码和当前资产基线，梳理 V3 全部 UI 行为、推荐、批量、预览、配置读写与计算/变量映射。补入当前缺失的推荐对照样本。
2. 拆共享 NC 基础服务与兼容分派，建立无环装配和两个专用插件；建立轨迹计划契约、预设资产和 V3 兼容策略，完成独立后端原始输入生成与旧 API 兼容。
3. 同步粗车完成表格、推荐/采用、左右独立生成、四通道预览和文件输出。
4. 越程槽完成类型/标准联动、多槽表、几何结果、左右生成和文件输出。
5. 接入轨迹预设选择/调整/保存、同源 2D、会话/草稿恢复、模板页转入、组合任务和历史快照，验证单插件启停。
6. 按 [nctool-verify](../../../.agents/skills/nctool-verify/SKILL.md) 做三层验收，交付逐行为报告和界面截图。

验收必须包含：

- Python/Rust 推荐候选、两位采用值、生成刀次、实际起点和同步游标对照；N 搜索边界、无解、零候选、舍入变更、连续多行、无需切削与左右通道覆盖。
- ES/FS 全标准及左右变换；类型切换草稿、失效标准、空行/部分行、非法几何和批量中途失败。
- 同一原始输入的最终 NC 程序对照，只容许预先列明的格式适配，不忽略值、同步号、通道和顺序。
- CLI/HTTP/WebUI 经专用服务直接从原始输入生成；不注入手算值；组合和完整文件导出验证。
- 浏览器实际完成填多行、推荐、采用、标准联动、2D、复制、导出和加入组合；覆盖普通/矮窗口、缩放等效视口、键盘操作、长表格与侧栏可达性。
- 保存冲突、原始草稿恢复、资源改变后失效、编辑期间旧响应、取消和历史环境变化。
- V3 兼容轨迹程序对照；预设复制、参数边界、适用类型/侧别/机床、导入导出和保存冲突；临时调整不修改默认，预设变化使旧结果失效。
- 轨迹计划与输出逐段映射、预览同源；耦合角度同时更新起点和运动，标准几何不可被覆盖；非法补偿转换、单边同步点、未知策略版本及不兼容模板拒绝生成；任一轨迹失败不交付部分通道。
- 冻结旧预设后修改当前资产，历史重执行仍使用旧快照；不可用旧策略明确失败，不自动迁移；组合任务冻结相同轨迹资源及确认状态。
- 关闭一个专用插件后另一插件及通用 NC 可用；纯模板构建无 NC 依赖；既有 28 模板迁移回归继续通过。

Rust workspace 检查带 `--workspace --locked`，默认与 NC target 分离，浏览器/CLI 用本轮临时 home/workspace。依赖变化执行审计。软件验收和机床工艺审核分别记录；不包含提交、推送或发布。
