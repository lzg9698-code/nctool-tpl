## 1. 产品目标与范围

主线：**打开工作区 → 选择或创建模板 → 填写参数 → 生成文本 → 复制/导出 → 从历史复用**。

| 类别 | 最终范围 |
| --- | --- |
| 保留 | MiniJinja 通用引擎、模板库/编辑器、嵌套 JSON 与精度校验、共享参数定义/预置/绑定/来源/冻结、通用受管渲染、草稿/冲突/任务/历史、资产包导入导出 |
| 保留 | 通用插件 SDK、运行时、依赖解析、版本化动作/服务、能力驱动页面、外部进程 JSON-RPC、取消/超时/终止和下次调用恢复、本地安装/配置/启停及通用资产集合贡献 |
| 独立保留 | 数学插件与数学过滤器，以独立 `math` feature 编译；插件启用和每次渲染的扩展选择均显式，选择进入输入签名和历史重放 |
| 彻底移除 | NC 生成、NC 参数与受管加工、机床、刀具/材料/加工标准、工艺计算、后处理/行号、同步粗车、越程槽、轨迹预设、多工序/加工组合及其专用模板编辑器 |
| 彻底移除 | `nc-bundle`、`--profile nc`、内置 NC 插件装配、专用服务/动作/资产集合、活动前端入口与代码、打包产物、现行加工示例/验收和发行承诺 |
| 兼容保留 | 最小旧配置识别、显式备份迁移、旧领域标记拒绝、旧历史只读、混合旧加工资产包整体拒绝、历史归档与恢复说明 |

“移除”指退出活动源码、依赖、运行时、界面、默认及全部可选构建、发行资源和当前维护文档；不能只隐藏菜单、默认禁用或改名保留加工实现。兼容识别只用于拒绝误执行和保护数据，不提供 NC 计算或后门执行。

通用模板仍能渲染任意文本，不对正文内容建立 G 代码识别器。带旧 NC 元数据/执行动作的资产不可默认为普通模板。通用插件协议保持开放，不内置针对所有第三方插件内容的分类器；已退役的内置插件 ID、动作/服务身份不能被同名外部插件接管以绕过兼容保护。

## 2. 成功标准

- **轻量**：默认构建只有通用模板与共享参数；数学可选；运行主程序不依赖 Node/Python。清理加工模块后测量二进制和首屏成本，基于同一环境比较。
- **完整**：创建、参数输入、生成、交付、历史恢复和迁移构成闭环；失败、取消、冲突、依赖变化和刷新恢复有明确结果。
- **易用**：常用流程就地完成；源码/Schema/绑定/插件配置渐进展开；错误明确指出原因和下一步。
- **可扩展**：外部非加工示例插件能够通过安装、预检查、启用、重启、调用宿主模板服务和产物导出完成验证；不为精简 NC 删除通用服务及生命周期机制。

保留精度、指纹、原子写入、冻结快照、取消和整批交付保障。多文件 artifact、原子目录交付属于通用基础能力，可继续保留；移除的是加工专用的工序与组合模型。

## 4. P0：彻底退出 NC，建立通用平台基线

4. 用户运行资产、配置、历史和浏览器草稿不作为删除目标。归档源码与运行资产备份分别说明。

### P0.2 Rust 与运行时收敛

- 从 workspace、CLI 依赖和装配删除 `plugins/nc`、`plugins/process`、`plugins/sync-turning`、`plugins/undercut` 及相关 NC 参数/受管实现；共享参数插件只保留通用模型。
- 删除 `nc-bundle`，添加独立 `math = ["dep:nctool-plugin-math"]`；默认 features 为空，默认组合为 template + parameters。
- 数学插件保持领域中立，不引入机床、工艺或 NC 后处理；构建可用、运行启用与单次 extensions 选择分别校验。
- CLI 运行配置仅支持 template；旧 nc profile 提供清晰兼容错误及显式迁移入口，不静默转换。
- 迁移先只读预检查，再显式确认 expected 指纹、备份并原子写入；启动不自动改写配置。数学启用状态及外部插件配置按实际依赖核对后保留，不能误删通用配置。
- 保留外部协议、插件依赖/服务绑定、通用动作 Schema、取消和进程生命周期；不因 NC 退出改动无关协议版本。

### P0.3 前端与数据边界

- 删除全部加工页面、专用编辑器、注册项、懒加载 chunk、表单分支、导航/设置选项和领域专用持久化调用；不只做隐藏。
- 清理 App、documentExecution、managedParameters 与 controller 中的 NC 放行、专用输入与选择路径；通用插件页面和共享参数控件继续工作。
- `metadata.nc`（包含 null/空对象）及退役 execution.action 不得降级普通/受管渲染；实际加载 include/import/extends 的冻结来源同样检查。
- 旧加工历史可查看、比较和导出原成功 artifact，不得重跑、试跑或恢复成可执行文档；不改写原历史。
- 导入包只要包含退役加工集合即整体拒绝，预检查阶段就报告；不得先导入通用部分。通用包正常导入，保留冲突与回滚语义。
- 新 UI 不读取或删除旧加工会话/资产以“清空遗留”。

### P0.4 工具、依赖、CI 与当前文档

- 架构检查正面验证：根引擎仅 MiniJinja，基础层/通用插件无 NC 依赖；默认树无 math，独立 math 构建有数学且无 NC；workspace、资源、打包和注册表无加工实现。
- Rust 门槛覆盖默认与 math；发行工作流改为 math 构建、template 默认配置，不再引用 nc-bundle/nc profile。
- 浏览器脚本去除 NC 正向生成，替换为通用/共享参数、数学显式扩展、非加工外部插件，以及旧加工配置/模板/历史/混合包拒绝场景。
- 清理实际无消费者依赖，定向更新锁文件并重新审计；不自动批量升级。网络失败保留为未完成。
- 同步 README、架构、系统设计、参数/模板/使用指南、贡献、发布、Skills 及变更记录。加工指南退出当前导航，保留适用历史的归档入口。
- 核对仓库 AGENTS.md 中仍按可选 NC 描述的条款并在实施时同步项目规则；全局规则不改。
