## 当前限制

- 模板引用的静态分析只枚举字面量；动态引用由实际渲染控制。MiniJinja 不等于完整 Python Jinja；小数/指数采用有限 f64，不提供任意精度小数。
- 草稿依赖浏览器存储容量与可用性，只有新版命名空间恢复。草稿不能代替已保存资产或备份。
- 任务历史记录版本、服务绑定及启动内容/公开配置摘要；不固定包外依赖、私密配置、外部环境与副作用，matching 不承诺字节级重现。
- 历史恢复为模板草稿仅支持普通和受管模板动作；任意插件动作可按自身契约重执行。旧加工历史只读。
- 历史查询仍扫描轻量索引并使用 offset 分页，解析缓存有容量和 2 秒重新读取边界；并发增删不提供快照一致性。产物为文本，未引入二进制附件存储。历史归档限制见运行维护。
- 外部插件运行同用户权限，进程隔离不是 OS 沙箱；安装/配置下次启动生效。资产包指纹不是来源认证，回滚不是跨插件事务。
- 运行时模板错误只有引擎当前暴露的模板标识；行列缺失时省略。解析错误的列为尽力定位。

## 第二轮优化与当前验证

已完成路线图的五项优先工作：

- 插件作者工具 scripts/check_plugin.py 独立运行实际宿主，覆盖握手、Schema、回调、取消、超时、迟到响应、同进程复用及槽位耗尽后的进程恢复；另以非法输出故障包证明会失败。测试配置和本地依赖只写入临时 home。
- 历史环境格式 2 记录启动内容指纹与公开配置投影摘要，提示具体宿主/插件内容或公开配置差异。私密值默认不参与摘要。单次 CLI 动作不写历史，跳过历史追溯开销。
- 当前宿主最近 256 次调用元数据通过 HTTP 和插件设置页查看，任务标识关联嵌套回调，不记录参数/配置/产物或错误正文。
- 历史摘要解析缓存有容量和时效边界；新增独立于插件启动的 history backup/restore/prune，保留策略先预览，再核对指纹并先备份；恢复只写新工作区，保留原记录字节。
- 哈希 JS/CSS 复用浏览器 immutable 缓存，HTML/API 保持 no-store。当前未增加运行时压缩或双份嵌入资源。

操作与边界见[运行维护](OPERATIONS.md)、[插件作者验收](PLUGIN_ACCEPTANCE.md)。本轮基于同一 Windows 环境、隔离源码与固定二进制比较；测量产物保留 SHA-256，不用历史发行数字代替本次数据。证据位于本机忽略目录 target/foundation-round2/。

代表性资产规模也已测量：固定 release 默认版、独立生成的 100/1000 份模板资产、各 5 次；每包分别约 0.14/1.41 MB。目录查询中位数约 56/200 ms，完整快照检查约 56/204 ms，实际 include 渲染约 56/198 ms；均包含新 CLI 进程启动、IO 与 JSON 序列化，并核对目录/快照数量和渲染正文。工具为 scripts/measure_assets.py，报告 assets-scale.json；1025 份的越界请求在生成前拒绝。当前不需要为该规模引入新存储引擎。

最后还修复了本机快速加载切换中透明 loading 图标残留污染按钮可访问名称的问题：使用已锁定组件库的全局装饰图标配置，执行按钮标记 busy 并阻止提交中的重复执行。新增单元回归通过；原插件浏览器脚本未放宽选择器或断言，连续 5 次通过后，再通过固定 release 的统一门禁。
