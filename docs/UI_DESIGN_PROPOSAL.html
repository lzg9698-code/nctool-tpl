一设计诊断

现状并不差——暗色工业 HMI 气质、三栏结构、实时预览都已到位，37 项验收全绿。问题集中在层级、反馈距离、长程序可导航性三处， 都是「功能都有，但用户要多走一步」的类型。

问题现状证据对用户的影响
主操作不突出 工具栏 5 个按钮同权重平铺：源码 / 预设 / 批量 / 复制 / 下载（index.html:587-601），仅靠颜色区分主次 每次生成后要在一排按钮里找「下载」，肌肉记忆建立慢
校验离输入太远 校验结果在右侧第 3 个 tab 内，而行列定位文本是模板源码坐标（「第 2 行第 68 列引用」） 填参数的人看到行列号无法定位到自己哪个输入框，必须来回切 tab
首次使用不自解释 空态只有一句「在左侧选择一个模板开始」 新手不知道模板是什么、该填几个参数、哪些必填
复用路径藏得深 「预设」是工具栏里的一个普通按钮；参数值刷新即丢失（验收 X-02 明确「不保留参数值」） 同一零件反复微调的场景，每次都要重填全部参数
长程序不可导航 预览是纯文本 + 轻量高亮；万行级输出（实测 1.77 ms / 203 KB）无目录、无跳转 核对工序边界要手动滚动查找，容易漏看
机床切换的心智位置错位 机床下拉在顶栏右侧，与「主题切换」「帮助」同级 机床是决定输出内容的输入，却看起来像界面偏好设置；切换后缺少「输出已变化」的显式反馈
状态反馈在视野外 「就绪 / 校验未通过」在页脚状态条（index.html:657），距操作点最远 错误提示容易被忽略，尤其在长表单滚动后
模态窗打断上下文 源码编辑 / 预设 / 批量 / 自定义机床全部是 modal-mask 模态（index.html:668+） 改源码时看不到预览，无法「边改边看」
移动端是「能看」不是「能用」 ≤480px 单列堆叠，参数面板与预览纵向互斥（验收 D-02-05/06 是在保证「预览不被压没」） 手机上填一个参数要上下滚动几次，无法边填边看结果
值得保留的资产：暗色工业 HMI 观感（琥珀主色 + 钢蓝次色）、单文件零依赖（可双击打开、可 include_str! 内嵌）、 演示 / 服务双模式、实时预览 + 防抖、行号 / 头注释 / ASCII 清洗等后处理开关——这些是本产品的差异化，不在重构范围内。

二设计目标与原则

目标一句话：把「一条直线任务流」做成界面的主轴，其余全部降为次级。

四条原则

  1. 结果优先——结果区在任何断点下都可见或一步可达；参数与结果不允许互相遮挡。
  2. 就地反馈——校验错误贴着出错的输入框，模板行列号作为次级信息附在后面。
  3. 渐进披露——必选参数永远展开；可选参数、源码、批量、自定义机床按需展开，不占主线。
  4. 状态可见——运行 / 成功 / 失败的状态出现在操作点附近，页脚状态条只做辅助。

三条硬约束（不可违反）

  • 零外部依赖：不引入框架 / CDN / 字体库，单文件可直接双击打开。
  • 契约不变：/api/templates、/api/inspect、/api/validate、/api/render、/api/part/generate 的请求与 {ok,data,error} 结构保持原样。
  • 逐字节一致：前端预览文本与 nctool render 输出必须逐字节相同（验收 D-04）；ui/index.html 与 cli/ui/index.html 必须保持字节一致。

三用户与核心任务流

界面习惯不是抽象的美学，而是「谁在什么场景下重复做什么」。按使用频次排三个角色：

角色目标使用频次界面必须为他做的事
工艺编程员（主） 把零件特征翻译成一份可上机床的 G-code 每天数十次，单次 1–5 分钟 参数填得快、错得少、能复用上次的参数、导出一步到位

8.3 错误呈现三层

  1. 字段级（最先看到）：输入框红框 + 就地一行原因，如「必填，未填写」；次级小字给模板坐标「模板第 2 行第 68 列引用」。
  2. 结果区摘要：状态 pill 显示「3 个问题」，点击展开列表，每条可点击 → 滚动到对应字段并聚焦。
  3. 状态条：一句话总状态，供扫视；aria-live="polite" 播报给读屏。
现状的「第 2 行第 68 列引用」对填参数的人不可读，方案把它降级为字段下方的次级信息， 主信息改为参数名 + 人话原因——保留信息，不丢失给模板开发者的定位能力。
