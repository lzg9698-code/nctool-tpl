# 切削与工时计算插件设计

日期：2026-10-24。状态：设计草案，未实施功能。本设计细化[插件扩展提案](MACHINING_PLUGINS_PLAN_2026-10-24.md)中的 cutting-tools；不授权插件实现、提交或发布。

## 1. 定位与首版范围

面向工艺工程师和数控编程人员，解决两件日常工作：给定切削数据换算转速/进给；给定实际进给路径估算理论切削时间。结果应能独立核算、导出并在历史中追溯。

本稿按“车、铣、钻基础换算 + 编程时分段工时核算”展开。这是尚未收到偏好选择时采用的默认范围；若用户希望先做单一工种或用于报价，应据此收敛范围后实施。

首版采用公制：长度 mm、切削速度 m/min、转速 r/min、进给 mm/r、mm/齿或 mm/min、时间 s。所有字段标题和输出均包含单位，不提供一个会改变全部数值解释的单位开关。

首版不建立材料/刀具/机床数据库，不自动推荐切削参数，不输出 NC 程序，不解析现有程序，不推算粗加工刀数，不模拟控制器。整件报价、批量摊销、英制、恒线速变径积分、钻尖与突破长度自动计算、啄钻循环、加减速模型和多通道重叠时间均不在首版范围。

## 2. 用户操作与界面

一个“切削与工时计算”插件面板，四个独立操作：车削计算、铣削计算、钻孔计算、分段工时。输入后点击现有“执行操作”，查看可读计算单、检查信息和实际输入，并复制或导出。

- 先填直径，再在切削速度/转速中填一个；进给也只选一种已知量填写。示例仅填一组合法已知量，不预填会与其他输入冲突的备选值。
- 车削/铣削可不填路径，只做参数换算；填入路径后增加该段工时。钻孔输入的是实际进给行程，可按相同孔数重复。
- 工时可以独立使用：输入各段实际路径、进给速度和重复次数，再按需填写已知辅助时间。
- 未提供辅助时间时，明确写“辅助时间未计入”，不把缺省当成 0。填写 0 表示用户明确声明这次核算不增加辅助时间。
- 修改输入后沿用宿主的过期结果门禁，禁止把旧结果当作当前输入导出。不同动作各自保留草稿与历史。

首版复用当前通用 Schema 表单与 ResultPanel。字段按 Schema properties 顺序排列，使用 title/description 解释单位与二选一约束；后端执行前校验组合。当前页面不提供条件字段联动、自动带入另一动作结果、专用结果卡片或可编辑工序表，不在设计中假定这些能力已经存在。

结果以文本计算单显示，CSV/JSON 作为可下载产物；不执行第三方前端脚本。若实际试用证明备选字段同时可见导致频繁输入错误，再单独评估宿主通用条件表单能力，不借本插件引入加工专用前端。

## 3. 四个动作及输入

插件 ID 为 `cutting-tools`，初始版本建议 `0.1.0`，外部协议 2；下列四个动作同时提供同名 v1 服务。动作 ID 使用新命名空间，不复用退役 NC 动作。

| 动作 | 用户目标 | 必填信息 | 可选信息 |
| --- | --- | --- | --- |
| `cutting.turning.calculate` | 车削转速/进给换算与恒转速单段工时 | 加工直径、一个速度已知量、一个进给已知量 | 实际路径、相同重复次数、转速上限 |
| `cutting.milling.calculate` | 铣削转速/进给换算与恒进给路径工时 | 有效切削直径、有效齿数、一个速度已知量、一个进给已知量 | 实际路径、相同重复次数、转速上限 |
| `cutting.drilling.calculate` | 钻孔转速/进给换算及相同行程孔的工时 | 钻头直径、一个速度已知量、一个进给已知量 | 实际进给行程、相同孔数、转速上限 |
| `cutting.time.estimate` | 汇总用户列出的恒进给段工时 | 各段实际路径、进给速度 | 名称、每段重复次数、已列辅助时间 |

### 3.1 三种切削动作的字段

| 字段 | 含义与约束 |
| --- | --- |
| `diameter_mm` | 必填且 > 0。车削为所核算位置的加工直径，铣削为该工况有效切削直径，钻孔为钻头直径 |
| `cutting_speed_m_min` | 可选且 > 0；与 `spindle_rpm` 恰好提供一个 |
| `spindle_rpm` | 可选且 > 0；允许理论小数转速，不隐式取整 |
| `feed_per_rev_mm` | 可选且 > 0；车削/钻孔可输入，铣削也支持按每转换算 |
| `feed_per_tooth_mm` | 仅铣削允许，可选且 > 0 |
| `feed_mm_min` | 可选且 > 0；与该动作其他进给已知量恰好提供一个 |
| `effective_teeth` | 仅铣削允许且必填，正整数。是计算进给所用的有效齿数，不按同时接触工件的瞬时齿数推算，也不自动读取刀具目录 |
| `path_length_mm` | 车削/铣削可选且 > 0；沿实际进给轨迹的物理长度，不是径向余量或 X 直径变化量 |
| `repeat_count` | 车削/铣削可选，默认 1；提供时必须同时提供路径，表示完全相同的路径和进给重复次数 |
| `feed_travel_mm` | 仅钻孔允许，可选且 > 0；单孔实际进给行程，由用户计入钻尖、引入、突破等所需长度，不自动等同于图纸孔深 |
| `hole_count` | 仅钻孔允许，默认 1；提供时必须同时提供进给行程，表示完全相同行程的孔数 |
| `max_spindle_rpm` | 可选且 > 0，仅作用户给定的限值比较；不据此静默限速或重算进给 |

所有字段缺省才采用上述默认值；null、空字符串和布尔值不作为数字或缺省接受。输入 Schema 拒绝未知字段，按动作限制可用字段，并用组合约束表达速度/进给的恰好一项；计算层再次核对这些业务约束。即使两个已知速度彼此一致，也拒绝同时提供，以避免隐含优先级。

### 3.2 分段工时字段

`segments` 为 1–500 行数组，每行有 `length_mm > 0`、`feed_mm_min > 0`、可选 `name`（最多 120 字符）、`repeat_count`（正整数，默认 1）。顶层可选 `title`（最多 120 字符）、`auxiliary_seconds >= 0`。重复次数和孔数均限制为 1–1,000,000，这是输入规模限制，不是机床能力限制。

每行只接受已经确定的实际进给速度，不嵌套另外一套切削计算条件。来自前一动作的结果可以由用户明确复制；首版不保留会在后台变化的跨动作引用。

各段按顺序串行求和；不处理并行工位或重叠动作。辅助时间是本次所列重复路径之外、由用户提供的一次性合计，只加一次，不自动乘每行次数。不再增加统一“效率系数”掩盖未建模项目。

铣削动作输入示例（`cutting.milling.calculate`）：

```json
{
  "diameter_mm": 20,
  "cutting_speed_m_min": 100,
  "feed_per_tooth_mm": 0.05,
  "effective_teeth": 4,
  "path_length_mm": 100
}
```

工时动作输入示例（`cutting.time.estimate`）：

```json
{
  "title": "已列工进段核算",
  "segments": [
    {"name": "重复切削段", "length_mm": 100, "feed_mm_min": 200, "repeat_count": 2},
    {"name": "精加工段", "length_mm": 30, "feed_mm_min": 120}
  ],
  "auxiliary_seconds": 20
}
```

## 4. 公式与工时边界

约定 `D` 为直径 mm，`vc` 为切削速度 m/min，`n` 为 r/min，`fn` 为 mm/r，`fz` 为 mm/齿，`z` 为有效齿数，`vf` 为 mm/min，`L` 为实际进给路径 mm，`k` 为重复次数。

| 计算 | 关系 | 适用范围 |
| --- | --- | --- |
| 切削速度/转速 | `n = 1000 × vc / (π × D)`；`vc = π × D × n / 1000` | 给定直径处的参数换算 |
| 每转/每分钟进给 | `vf = fn × n`；`fn = vf / n` | 三类加工 |
| 每齿进给 | `vf = fz × z × n`；`fz = vf / (z × n)`；`fn = fz × z` | 铣削 |
| 单段工时 | `t_seconds = 60 × L × k / vf` | 所列路径保持恒定进给 |
| 相同钻孔工时 | `t_seconds = 60 × feed_travel_mm × hole_count / vf` | 不含快移、退刀、停留和啄钻附加动作 |
| 多段切削时间 | `cutting_seconds = Σ t_seconds` | 串行的已列路径 |
| 已列项目合计 | `listed_total_seconds = cutting_seconds + auxiliary_seconds` | 仅在用户明确填写辅助时间时提供 |

车削恒转速时，可针对端面或锥面给出恒定物理路径进给的时间；该直径仅用于切削速度的局部换算，不表示整条变径路径维持同一切削速度。恒线速端面/锥面的转速随直径变化，首版不能用一次换算结果代表整段积分；需用户另行分段并明确估算假设。

铣削球刀/圆鼻刀等使用有效切削直径，不在缺少切深等数据时擅自用标称直径替代。钻孔的排屑停留、啄钻退刀等必须另行列入辅助时间或保持未计入。

## 5. 输出、诊断与追溯

每次成功返回标准 ActionResult：结构化 `data`、文本 `artifacts`、结构化 `diagnostics`。不增加宿主 HTTP/RPC 字段，不要求启用 math，不依赖模板或共享参数资产。

三种切削动作的 data 包含 `calculation_version: "cutting-v1"`、`operation`、归一化输入、`results`、`assumptions`、`formula_sources`、`text`。results 总是返回转速、切削速度、每转进给和每分钟进给；铣削另返回每齿进给与有效齿数。未请求工时则 `cutting_seconds` 为 null，不填 0。

工时动作额外给出各段小计、切削合计、`auxiliary_status`（`provided` 或 `not_provided`）、辅助时间和已列合计。辅助时间缺省时后两项为 null；任何合计都明确标为“已列项目”，不声称完整实际循环节拍。

三种产物按固定顺序返回：`cutting-report.md`、`cutting-results.csv`、`cutting-result.json`；首份计算单包含输入/单位、已知量、结果、使用公式、假设、警告与未计入项。CSV 包含明确单位，使用标准转义并防止用户名称被电子表格当作公式；JSON 保存结构化数值而非显示舍入值。全部通过宿主导出，不直接写用户目录。

数值采用有限双精度计算，中间值不按显示精度舍入。计算层校验所有派生结果有限、应为正的量仍 > 0；溢出、非零正值下溢到 0 或无法表达的结果明确失败。显示转速 2 位、切削速度 3 位、进给最多 6 位、秒数 3 位；若舍入会显示成 0 则使用科学计数法。结构化结果保留计算精度，不输出取整后的机床 S/F 指令。

| 情况 | 行为 |
| --- | --- |
| 缺字段、互斥字段同时填写、未知字段、非法数字、次数不合法 | 失败；诊断给字段路径，不生成可交付文件 |
| 计算溢出/下溢或结果无效 | `calculation_range` 错误，指明关联输入，不输出 NaN/Infinity |
| 计算转速超过用户给定上限 | 成功但有 `spindle_limit_exceeded` 警告；原理论结果保留，所有报告写明未限速 |
| 未填写辅助时间 | 成功，状态明确未计入，不默认推算或补零 |
| 取消、超时、失败或当前输入已变更 | 使用宿主状态与交付门禁，不返回部分文件冒充完整结果 |

输入与计算版本进入任务历史；没有外部资产，原始输入足够重执行，不另造 replay_input。插件更新后宿主显示环境差异，报告保留当时版本；重执行不保证跨版本结果逐字相同，也不修改旧历史。

## 6. 实现组织与交付

插件源码放在宿主仓库之外的独立项目，不加入当前 Rust workspace。采用 Python 3.9+ 和标准库，沿用现有 Python SDK 的协议实现；分离纯计算、输入校验、报告输出和协议适配。发布包带 plugin.json、入口、SDK 固定副本及说明，注明所依据的宿主/SDK 提交，不从运行时工作区导入宿主源码。

descriptor 的 requires 为空，provides 声明上述四项 v1 服务，panel.view 为 form。建议 timeout 30,000 ms、max_message_bytes 1 MiB、max_concurrency 4；业务输入另设数组/字符串限制。max_message_bytes 约束完整 JSON-RPC 编码（含三份产物），超限返回明确错误，不能依赖截断结果。

Windows 的 command 指向部署时明确选择的 Python 可执行文件，不依赖一定存在 python3 别名。首版不打包解释器，不联网取数据，不自建持久化资产；输入复用依靠宿主动作草稿、历史和显式 JSON 导出。

建议交付顺序：纯计算与算例 → 四动作 Schema 和标准报告 → 实际宿主安装/历史/导出 → 脱敏工作样本试用。试用重点记录重复录入、二选一字段出错、漏计时间及理论/实测差异，再决定专用表单或下一版本功能。

## 7. 验收算例与场景

下表为独立公式算例，非已实现插件的测试结果。比较未舍入值：`abs(actual - expected) <= max(1e-9, abs(expected) × 1e-9)`；报告显示另按显示规则校验。

| 场景 | 输入摘要 | 预期 |
| --- | --- | --- |
| 车削已知转速 | D=50，n=1000，fn=0.2，L=100 | vc≈157.0796326795，vf=200，t=30 s |
| 铣削已知切速 | D=20，vc=100，fz=0.05，z=4，L=100 | n≈1591.54943091895，vf≈318.309886183791，t≈18.84955592154 s |
| 钻孔相同行程 | D=10，n=2000，fn=0.1，进给行程=25，孔数=6 | vc≈62.83185307180，vf=200，t=45 s；不含孔间快移 |
| 多段合计 | L=100、vf=200、重复2次；L=30、vf=120、重复1次；辅助20 s | 切削=75 s；已列合计=95 s；辅助只加一次 |
| 辅助未知 | 与上例相同但省略辅助时间 | 切削=75 s，辅助状态 not_provided，辅助和已列合计为 null |
| 辅助明确为0 | 与上例相同且辅助=0 | 切削=75 s，辅助状态 provided，已列合计=75 s |
| 超转速 | 铣削算例附 max_spindle_rpm=1500 | 转速仍≈1591.54943，返回超限警告，不静默调整 vf/工时 |

其他必须覆盖：速度/进给逆向换算；两项同时提供与全部缺失；直径为0/负数；铣削缺齿数/非整数齿数；重复次数与路径缺失组合；对象含未知字段；null/布尔/字符串数字；极小/极大数的计算范围；501段拒绝；次数上限；中文和逗号换行名称导出；CSV 公式注入；显示舍入不改变工时；完整消息体积上限。

集成验收按[插件作者验收](PLUGIN_ACCEPTANCE.md)运行真实宿主：握手与描述、四动作 Schema、服务调用、成功/非法输入、取消/超时/恢复。无宿主回调时明确标为不适用；测试专用构建注入等待与故障，不给生产计算动作加入等待字段。

浏览器使用临时 home/workspace 与随机端口，验证三类参数换算、工时数组、错误提示、动作切换、历史重执行、三份文件复制导出、改输入后旧结果禁止交付。静态算例与 UI 验收通过不等于实际机床节拍或加工参数适用性已经验证。
