> 适用版本：nctool-cli ≥ 0.2.1
> 启动方式：`nctool ui --host 127.0.0.1 --port 8787`，浏览器打开 `http://127.0.0.1:8787`。
> 本清单覆盖 ROADMAP 阶段 D 的全部验收项 + D4.3 机床切换，D 完成后必跑。
> 配套：`cli/tests/cli_e2e.rs` 覆盖 10 个 CLI 子命令的退出码契约；本清单是**人工端到端**那一层。
>
> 走查记录（2026-09-10，nctool-cli 0.2.1，Chrome 产品浏览器）：37/37 通过。
> 移动端 §2 采用 375px 同源 iframe 模拟 ≤480px 视口（媒体查询真实生效）验证；
> D-02-05/07/08 经静态 CSS + 布局实测确认。本次走查修复 3 个前端缺陷
> （参数必选/默认值解析、数据源文本、移动端输入框字号），见 CHANGELOG。

## 1. 全链路（验收项 D-01）

> 选模板 → 填参 → 预览 → 校验 → 下载，端到端手工跑通。

- [x] **D-01-01** 左侧模板列表点击 `drill_cycle`
  - 中间表单显示 4 个必填参数（`x` / `y` / `depth` / `feed`）+ 1 个可选（`r_plane`，默认 5.0，规格层口径，与 `nctool validate` 一致）
  - 右侧 G-code 预览出现（带或不带行号均可），含 `G0 X... Y...` / `G98 G81` / `G80`
- [x] **D-01-02** 填入：`x=21` `y=15` `r_plane=5` `depth=-10` `feed=100`
  - 300ms 防抖后预览刷新（看 Network：`POST /api/render` 200）
  - 状态栏变绿，文字「就绪」，右侧出现「N 字符 · 1 行」与「渲染 0.x ms」
- [x] **D-01-03** 切到「校验」tab
  - 「校验」标签后无错误计数（绿色 0）
  - 没有红字 issue
- [x] **D-01-04** 故意清空 `x` 字段
  - 「校验」tab 出现红字「`x` 必选参数缺失（第 1 行第 24 列引用）」
  - G-code 预览清空，显示「校验未通过，修正参数后将实时显示 G-code」
  - 状态栏文字变红「校验未通过」
- [x] **D-01-05** 恢复 `x=21`
  - 预览自动恢复
- [x] **D-01-06** 点预览工具栏的「下载」
  - 浏览器下载 `*.nc` 文件
  - 文件内容与右侧预览**逐字相同**（含行号、注释、空行）
  - `diff <(cat ~/Downloads/xxx.nc) <(echo "<预览内容>")` 无差异
- [x] **D-01-07** 点「复制」
  - 状态栏短暂显示「已复制」toast
  - 剪贴板内容与预览一致
- [x] **D-01-08** 关闭浏览器再打开，模板选中状态保留（前端 state 在同会话内有效；不要求跨刷新）

**通过条件**：8 项全过。如 D-01-06 不一致 → 报告 D-R2（防抖/渲染漂移），先关掉防抖确认。

## 2. 移动端 ≤480px（验收项 D-02）

> 移动端可读可点，控件不遮挡预览。

- [x] **D-02-01** 浏览器 DevTools 切到 iPhone SE（375×667）或自定义 480×800
- [x] **D-02-02** 检查字号：所有 input/select/textarea 渲染的**视觉字号 ≥ 16px**
  - 触发 iOS Safari 聚焦时若 < 16px 会自动放大整页（项目已强制 16px）
- [x] **D-02-03** 触摸目标：所有按钮、tab、chip 的**点击区高度 ≥ 38–40px**
- [x] **D-02-04** 顶栏压缩：品牌 + 必要操作可见，无溢出/换行
- [x] **D-02-05** 侧栏（模板列表）限高 ≤ 220px，**保证下方预览不被压没**
- [x] **D-02-06** 工作区单列：参数面板在预览面板上方/下方纵向排布，**互不遮挡**
- [x] **D-02-07** 参数行允许换行：单位/范围不再把标签挤出屏幕
- [x] **D-02-08** 预览工具条换行、隐藏 spacer；代码区字号 ≤ 12px
- [x] **D-09** 选项卡（实时预览 / 模板源码 / 校验）横向可滚动，无变形
- [x] **D-10** 关于 / 帮助键值列表改单列
- [x] **D-11** 在 ≤480px 下完整跑一遍 §1 全链路

**通过条件**：11 项全过，**特别是 D-02-05 / D-02-06**——侧栏过高或工作区多列会直接让预览消失。

## 3. 校验面板定位（验收项 D-03）

> 校验面板能定位到具体参数。

- [x] **D-03-01** 选 `program_header`，仅填 `prog=1234`，不填其他
  - 校验面板应列出 `part_name` / `op_name` 的报错（如有）
- [x] **D-03-02** 选 `drill_cycle`，少填 `feed`
  - 校验面板：「错误 [feed] 必选参数缺失（...）（第 2 行第 68 列引用）」
  - 行列定位文本格式：`第 N 行第 M 列引用`
- [x] **D-03-03** 类型不匹配（`x="abc"`）
  - **UI 层不可达**：`type=number` 控件物理上拒绝非数字输入（value 被清空），无法触发类型不匹配
  - 后端类型不匹配已由 API/`cli_e2e` 测试守护（本项无需人工验收，仅记录）
- [x] **D-03-04** 在 `safe_move` 设 `safe_z=-5`（违反规格 min=0）
  - 校验面板：「错误 [safe_z] 参数值 -5 mm 低于下界 0（第 1 行第 28 列引用）」
- [x] **D-03-05** Network 面板：`POST /api/render` 返回 200，响应含 `data.issues[]`（校验内联在渲染响应，无独立 `/api/validate` 端点），每条 issue 至少含 `level` / `param` / `message`

**通过条件**：5 项全过。D-03-05 是后端契约，配合 `cli/tests/cli_e2e.rs::validate_*` 一并守护。

## 5. 机床切换（验收项 D4.3）

> 切换机床预设，预览 G-code 中的 G/M 码应随之变化。

- [x] **D4.3-01** 顶栏「机床」下拉选 `generic` → 切到 `wfl_m65`
  - 预览头部注释（若开 `addHeader`）的 `( template: ... )` 后无变化
  - `program_header` 的程序号前缀仍是 `O`（两者默认相同）
- [x] **D4.3-02** 自定义机床：在 `nctool.toml` 注册：

  ```toml
  [machine.hero_x9]
  id = "hero_x9"
  vendor = "HERO"
  model = "X9"
  [machine.hero_x9.config]
  program_prefix = "P"          # 改 Mazak 风格
  program_digits = "5"
  line_number_digits = "5"
  coordinate_system = "G54"     # 注意：自定义机床需提供模板引用的全部 machine 键，
  feed_mode = "G94"             # 缺失键在严格模式下渲染直接失败（防御行为）
  ```

  ```bash
  nctool config init   # 已有就跳过
  nctool ui --host 127.0.0.1 --port 8787
  ```

  重新选 `program_header`，填 `prog=1234`
  - 预览 G-code：`P01234`（不是 `O1234`）
  - 行号若开：`N00010`（5 位）
- [x] **D4.3-03** 切回 `generic`，预览恢复 `O1234`
- [x] **D4.3-04** `nctool machine show hero_x9` 在 CLI 正常显示机床详情（**不是**「未知机床」）
  - CLI 与 UI 服务读同一层叠配置：同一目录下 `nctool.toml` 对两边同时生效
  - 排查：先用 `nctool config show` 确认 hero_x9 在「自定义机床」列表里

**通过条件**：4 项全过。如 D4.3-02 切换无变化 → 检查 `nctool config show` 的 `default_machine` 段。
