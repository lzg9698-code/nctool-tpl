# 机械加工工艺与数控编程插件扩展计划

日期：2026-10-24。状态：供讨论的规划，未授权实施、提交或发布。

## 1. 方向与现状

目标是减少工艺工程师和数控编程人员日常的重复计算、坐标核算、资料整理和程序人工检查。先交付能独立使用、能用算例核验的小工具，再逐步连接工作流。

当前工作区的 `Cargo.toml`、`sdk/src/lib.rs`、`ui/src/features/plugins/ActionPage.tsx` 与[插件协议](PLUGIN_PROTOCOL.md)表明：

- 默认组合是 template + parameters，math 为可选扩展；加工领域实现不进入当前 Rust workspace、核心引擎或内置发行组合。
- 外部协议 2 已支持动作、服务调用、JSON Schema 校验、通用表单、结构化诊断、任务取消和执行历史。适合先以独立目录安装的外部插件落地。
- 通用动作页可输入参数并查看结果，但目前不能安装第三方前端脚本。交互式轮廓编辑、专用工艺表格和复杂图形预览需要另外规划宿主通用能力。
- 当前 `Artifact` 只携带文本。第一版采用 JSON、CSV、Markdown 和 NC 文本输出；XLSX、DOCX、PDF 的二进制交付需要单独设计，不假定当前协议直接支持。
- 本轮没有修改源码。开始时已有未跟踪 `.codex/`、`memory/`，均保留。

启动简报实际位于 `D:/ai-brain/memory/projects/nctool-rustjinja/_brief.md`，其中版本和发布信息早于当前仓库；规划以当前源码和文档为准。

## 2. 建议的六个插件

优先级按预期日常使用频率、可核验性、实现依赖和错误影响排序，仍需用实际工作样本校正。

| 插件 | 日常任务 | 第一版范围 | 暂缓内容 | 顺序 |
| --- | --- | --- | --- | --- |
| 切削与工时计算 `cutting-tools` | 换算转速、进给；估算单段切削时间 | 车/铣/钻基础换算；每转、每齿、每分钟进给显式区分；输入路径长度后的恒定进给时间 | 自动推荐材料/刀片参数、整件节拍预测、恒线速变径积分 | 第一批 |
| 坐标与几何计算 `geometry-tools` | 算孔位、锥度、坐标变换、轮廓关键点 | 孔圆分布、二维平移旋转、锥度/斜线；明确车削 X 直径值与半径值 | 自动刀补、五轴运动学、交互式完整轮廓建模 | 第一批 |
| 工艺文件助手 `process-docs` | 编工序卡、刀具清单、装夹说明、检验清单 | 人工编制工序与刀具表，模板生成 Markdown/CSV；完整性检查 | 自动识图、自动排工艺、ERP/MES 对接、原生 Office 排版 | 第二批 |

| NC 程序静态检查 `nc-review` | 找单位、模态、刀具/补偿引用、程序结构问题 | 选定一种系统和一种机床类型，解析受支持语法；输出行号、规则依据、严重程度和检查覆盖范围 | 碰撞证明、完整宏解释执行、控制器仿真、所有系统通用检查 | 第三批 |
| 参数化程序片段 `nc-snippets` | 重复编孔位、简单循环与标准程序段 | 选定系统的一种简单加工模式；冻结输入和模板，输出程序、参数摘要与检查报告 | 通用 CAM、全工件自动编程、多通道同步、五轴联动 | 第四批 |

### 2.1 切削与工时计算

详细动作、字段、工时边界、界面约束和验收算例见[切削与工时计算插件设计](CUTTING_TOOLS_DESIGN_2026-10-24.md)。该设计仍为草案，尚未实施。

输入包含加工类型、明确单位、有效切削直径、切削速度或转速、进给定义与必要的有效齿数。输出包含结果、单位、公式、输入摘要及假设。首版由用户提供切削数据；不把公式换算包装成刀具参数推荐。

示例：有效直径 20 mm，切削速度 100 m/min，每齿进给 0.05 mm，有效齿数 4，预期转速约 1591.55 r/min、进给速度约 318.31 mm/min。计算保留内部精度，显示和程序导出分别约定舍入方式；机床转速上限超出时提示，不静默截断。

工时首版只算明确路径长度、恒定进给下的理论切削时间；装夹、换刀、加减速、快移和人工辅助时间分别输入或标记未计入。

### 2.2 坐标与几何计算

输入明确坐标系、原点、角度单位、角度零方向、顺逆时针及输出顺序。输出坐标表、计算说明、CSV/JSON；车削先在物理几何坐标中计算，再显式转换 X 直径输出。

孔圆应区分整圆等分和指定角度范围，禁止产生无意的首尾重复点。直线/圆弧求交与相切点放在后续小版本，须明确多解选择、相切容差与无解诊断。

### 2.3 工艺文件助手

第一版围绕“零件基本信息 → 人工工序清单 → 刀具/装夹/检验要求 → 文档导出”。允许只做一张刀具表，不强制维护整套工艺模型。

复用现有模板渲染服务，先保证参数录入、表格行顺序和文本导出可用。字段较多时先验证通用表单的操作成本；若效率不足，再独立提出可复用的宿主表格编辑能力。首版通过显式输入/导入导出保存文档，不另建绕过 JsonStore 的宿主资产文件。

### 2.4 尺寸与余量核算

先支持“已知偏差的确定性计算”。孔轴配合返回最小/最大间隙和配合分类；余量注明单边、双边或直径量；尺寸链明确各组成环方向。单位换算和输出舍入不得改变公差判定。

后续标准查询必须先确定使用的标准、版次、尺寸分段边界及合法数据来源。螺纹底孔等经验推荐应独立标识，不能与标准规定值混写。

### 2.5 NC 静态检查

首先固定“控制系统系列 + 软件/手册版本 + 车床或铣床 + 机床约定”。SINUMERIK、FANUC、Haas 等适配按实际使用情况择一，不在首版同时承诺支持。

第一版只读检查：语法/程序结构、可确定的模态组冲突、进给与单位状态、可解析的刀具和补偿引用，以及用户明确提供的转速限制。缺少初始状态或机床约定时报告未知；不能把“文件开头没有某条指令”直接认定为通用错误。

遇到宏变量、条件跳转、外部子程序、坐标变换或未知 OEM 指令，列出未解析范围及其后续影响；必要时将受影响分析结果标为未知。输出“支持范围内发现的问题”，不输出“程序安全可上机”。

### 2.6 参数化程序片段

在静态检查基础和目标系统确定后，选择一种高频模式试点，例如孔圆坐标程序段。控制器语法、坐标模式、刀补责任、进退刀条件和程序边界必须明确；不把不同系统语法混入同一默认模板。

用户先检查参数与坐标表，再生成程序段和报告。模板与参数冻结绑定，输入变更后旧结果标记过期。机器验证仍需对应控制器/仿真与实际装夹条件；离线单元测试仅证明受测输出。

## 3. 技术落地

1. 加工插件源码位于独立仓库或本仓库之外的独立项目；每个插件独立版本、安装与启停，不恢复旧 NC profile、旧动作 ID 或旧加工资产执行。
2. 第一批优先采用现有 Python SDK，降低验证成本；以实际工作负载决定是否需要 Rust 实现。Windows 安装包明确解释器路径，是否打包运行时在试点后决定。
3. 每个插件可包含多个小动作，但只维护自身领域数据。不先建材料、刀具、机床的全局管理平台。
4. 输入采用明确的 Schema 和单位，后端校验有限数、范围与跨字段约束。字段标题写清单位，不假定 `ui_schema` 的全部显示提示已被当前前端消费。
5. 统一业务输出约定：结果、单位、计算/规则版本、假设、来源、未覆盖范围；宿主 `diagnostics` 提供错误与警告，`artifacts` 提供文本交付物。此为新插件约定，不要求改动宿主协议。
6. 跨插件通过版本化服务或显式文件交换。首版允许手动复制结果，等真实流程证明必要后再做自动串联。
7. 如确需领域资产集合，另行定义服务、预检查、冲突和 receipt 回滚契约，通过宿主存储边界实现；不直接写用户模板或历史目录。
8. 外部插件以用户权限运行；进程隔离不是操作系统沙箱。首版不接机床、不自动发送程序、不默认联网，也不在日志中复制完整生产程序。

## 4. 分阶段交付与门槛

| 阶段 | 交付物 | 完成条件 |
| --- | --- | --- |
| A：场景与契约确认 | 高频任务清单、脱敏算例、动作输入/输出草案 | 按实际车/铣占比确定首批功能；NC 阶段前明确系统与机床约定；每个首版动作至少有正常和错误样本 |
| B：计算工具试点 | 切削、几何两个独立插件安装目录、说明与验收报告 | 典型算例、逆向核算、单位/边界验证通过；实际宿主安装、表单输入、结果导出、历史重执行完成 |
| C：工艺工作流 | 工艺文档、尺寸余量插件 | 一个脱敏零件从尺寸核算到工艺文档完整走通；遗漏字段有提示；用户能核对计算和文档 |
| D：NC 检查 | 单系统、单机床类型检查器与规则清单 | 每条规则有应报/不应报对照；未知语法不误报全量检查通过；保留误报与漏检评估记录 |
| E：程序片段试点 | 一种加工模式、参数模板、输出和验证说明 | 算例坐标与程序一致；模板/参数快照可追溯；控制器或仿真验证结果单独记录 |

各阶段单独评审范围和结果。第一轮建议只推进 A、B，不同时开六个插件。工期在 A 阶段确定样本、功能和部署方式后估算。

## 5. 验证计划

- 数值：独立手算或第二种计算方法核验；单位往返、边界尺寸、零/负值、有效齿数、极小/极大输入；无解与多解；按工程精度定义误差限。
- 业务：选用脱敏实际工作样本；工时核算区分估算与实测；尺寸链覆盖方向和极限组合；NC 规则同时覆盖应报与不应报程序。
- 协议：按[插件作者验收](PLUGIN_ACCEPTANCE.md)使用 `scripts/check_plugin.py`，覆盖握手、Schema、依赖回调、取消、超时、迟到响应和恢复。计算很快的插件用专门测试构建注入故障，不给生产动作添加等待参数。
- UI：临时 home/workspace、随机 loopback 端口，验证正常输入、半成品数字、报错、切换动作、取消、结果过期和文件导出；通用表单不满足实际录入时记录差距。
- 重放：固定业务输入和公式/规则版本；插件程序或规则变化时如实显示环境差异，不承诺所有历史在新版本产生完全相同结果。
- 如需宿主变更，再按受影响组件运行当前贡献指南中的检查；本规划轮未运行产品测试，不代表上述门槛已通过。

## 6. 后续需要收敛的信息

实施前确定：车削/铣削占比、最常重复的三项任务、主要控制系统与机床类型、可提供的脱敏样本、Windows 插件部署方式。无需为此预先建立庞大设备数据库。

第一批建议的最小闭环是：“算转速和进给 → 算孔位或锥度 → 导出可核对的计算单”，后续再连接工艺卡、程序检查和程序片段。
