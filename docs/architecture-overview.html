01分层架构

依赖严格单向向下：cli → core → tpl → minijinja。所有业务逻辑在 core，CLI 与 Web UI 只是两个输入/展示面。

02端到端数据流

主线是「渲染前可发现错误」：校验失败时 stdout 不含任何 G-code，报告走 stderr。

03参数规格的三个来源

优先级：清单 params > variables.yaml > 头部 {# PARAMS: #}。三者共用同一套稀疏覆盖机制，只写要改的字段。

05模块速查

Crate模块职责
tplextract.rsAST 遍历提取变量，区分可选/必选（兜底不向下传播）
tplfilters.rsNC 数值格式化 + 数学过滤器；度制用 _d 后缀，全部做有限性校验
tplrenderer.rsminijinja 环境封装；严格为默认，宽松需显式开启
coremodel.rs扁平值模型 + 规格构建器 + 机床配置
coremanifest.rs清单与头部元数据三级回退；merge_params 稀疏覆盖
corevariables.rs全局按名变量库；刻意不导入 default_value
corederive.rs派生参数查表计算；派生值恒胜且照常过校验
corevalidate.rs15 类 IssueKind 结构化问题；白名单独立检查
coreregistry.rs模板注册表；extract_params/validate 穿透 include 闭包
corepipeline.rs校验 → 派生 → 兜底 → 渲染 → 后处理；宽松模式仍硬拦 NaN·Inf
clicontext.rs递归装载模板目录，逐模板解析元数据与规格
cliserver.rs回环地址 HTTP API；规格 JSON 形状的单一来源
